# SIVIA ModelAtlas

Independent parallel project; never modify adjacent Sivia checkouts as an implementation shortcut.

Primary purpose: draw figures from existing MCM/ICM paper drafts, especially draft → overview.
Do not solve contest problems or write papers unless separately requested. The main skill is
draft2overview: manuscript understanding → actual reference-page viewing → design/full prompt →
host ImageGen → visual review/correction → actual image/prompt/evidence pairing.
The basic workflow-node renderer and quantitative recipes are secondary tools, not the product definition.

The manuscript governs scientific content. Reference papers guide composition only. Keep verified
O/F award references separate from research/preprint extensions and ordinary search records.
Classify by original year/problem, transferable A–F profiles, role and method; problem F is not
award F. Store official COMAP team/award proof and fixed source version/SHA/page/figure.
A downloaded PDF is not a viewed figure. Changed source bytes must fail, not silently re-pin.
Use AnySearch discovery first, including exact team/official web searches when academic coverage is weak.

Runtime intake does not understand a paper or generate an image. Never label prepared sessions as
drawn overviews. Actual generation is a host capability. Quantitative plots use real supplied data;
never ask image generation to invent points/metrics/uncertainty. Mark test/demo inputs explicitly.
Keep file integrity checks, assistant visual review and user acceptance separate.

Store private drafts, source PDFs, page renders and credentials only in ignored local state.
Public source availability does not grant redistribution permission. Keep independent Git history,
use codex/ branches and run tests/build before release. New style cases require visual inspection;
scientific claims and reference defects must not be copied into user figures.
